# 👑 PROFESSOR — منظومة الاشتراكات والمسوقين المتكاملة

> **النسخة الحالية:** Ecosystem V2 (تطبيق + سيرفر + بوت تليجرام موحّد)
> **الهدف:** إدارة بوت الاشتراكات وبوت المسوقين **بالكامل من تطبيق أندرويد واحد**، مع بقاء تليجرام واجهة تفاعل للمستخدمين وتنبيهات فقط للأدمن.

## <a name="2"></a>🚀 2. البدء السريع (للمالك)

### 2.1 تشغيل السيرفر

```bash
pip install -r requirements.txt
python main.py          # أو: uvicorn main:app --host 0.0.0.0 --port $PORT
```

- **المنفذ:** يُقرأ من `SERVER_PORT` ثم `PORT` ثم الافتراضي `8000`.
- **KataBump:** اضبط متغير البيئة `SERVER_PORT` على المنفذ المعطى لك، واستخدم الـ IP الخارجي مع منفذ التوجيه في التطبيق.
- لا تحتاج أي توكن داخل الملفات — **كل التهيئة تتم من التطبيق** بعد الربط.

### 2.2 الربط من التطبيق

1. افتح التطبيق ← شاشة المنظومة ← أدخل **رابط السيرفر** فقط (اترك مفتاح API فارغاً أول مرة).
2. التطبيق ينشئ مفتاح `prof_...` تلقائياً عبر `/api/pair/claim` ويحفظه (ونسخة في `PROFESSOR_API_KEY.txt` بجانب main.py).
3. افتح **شاشة التهيئة** داخل التطبيق وأدخل: اسم البراند، آيدي الأدمن، رابط الدعم، **توكن البوت**، آيدي القناة الخاصة (VIP)، آيدي القناة العامة، روابط القناة/المؤشر، مدد الاشتراك، رسائل البوت.
4. اضغط **🤖 اختبار البوت والقنوات** (النتيجة بالعربية) ثم **💾 حفظ وتشغيل المنظومة**.
5. ارفع البوت **مشرفاً** في القناتين (إنشاء روابط الدعوة يتطلب صلاحية المشرف في القناة العامة).

### 2.3 بناء التطبيق

- البناء عبر **GitHub Actions** (JDK 17) — ادفع المشروع للمستودع وشغّل الـ workflow لتحصل على APK.
- `usesCleartextTraffic="true"` مفعّل في الـ Manifest لأن KataBump يعمل HTTP.

## <a name="3"></a>🗄️ 3. بنية الملفات والبيانات

كل البيانات تُخزن كملفات JSON في مجلد `data/` بجانب `main.py` (يُنشأ تلقائياً):

| الملف | المحتوى | ملاحظات مهمة |
|---|---|---|
| `config.json` | كل الإعدادات: البراند، الأدمن، التوكنات، الآيديهات، الروابط، **المدد**، **كل نصوص الرسائل** | مفاتيح الرسائل: `subscription_messages` + `marketing_messages` |
| `subs_data.json` | `pending_subs` (طلبات معلقة)، `active_subs` (مشتركين + تواريخ الانتهاء + `notified_1day`)، `stats` (الإيراد + العدد) | التواريخ بصيغة `%Y-%m-%d %H:%M:%S` |
| `prof_crm.json` | نظام المسوقين كاملاً: `whitelist`, `referrals`, `public_leads`, `active_links`, `marketers_data`, `pending_requests`, `historical_clients`, `withdrawal_requests`, `paid_count`, `total_joined` | نفس هيكل ملف البوت القديم للتوافق |
| `notifications.json` | إشعارات التطبيق — **آيدي متزايد دائم ولا يُصفَّر** + حالة `read`/`handled` | سعة ثابتة **100** (FIFO — يُحذف الأقدم فقط عند الامتلاء؛ ولا حذف آخر إلا من 🗑️) |
| `admin_alerts.json` | مراجع رسائل تنبيهات الأدمن في تليجرام (`chat_id`,`message_id`,`text`,`active`) | أساس مزامنة إلغاء الأزرار |
| `server_auth.json` | مفتاح API + معرف العميل | لا تشاركه |
| `PROFESSOR_API_KEY.txt` | نسخة نصية من المفتاح | تُنشأ عند أول ربط |

## <a name="4"></a>🔐 4. الأمان ونظام الربط

- كل مسارات `/api/*` محمية بميدلوير يتطلب الترويسة `X-API-Key: <key>` أو `Authorization: Bearer <key>`.
- **المسارات العامة الوحيدة:** `/api/health`, `/api/pair/status`, `/api/pair/claim`.
- `/api/pair/claim` ينشئ المفتاح **مرة واحدة فقط**؛ أي محاولة بعدها تُرفض `409`.
- `/api/server/key` يعيد المفتاح — محمي أيضاً بالمفتاح نفسه (زر 🔑 في التطبيق يفتح **شاشة منبثقة أنيقة** تعرض المفتاح كاملاً ملتفاً على أسطر مع زر **📋 نسخ المفتاح كاملاً**).
- الخطأ يعود `401 {"ok": false, "error": "Invalid API key"}` نظيفاً.
- يمكن تثبيت مفتاح إجباري عبر متغير البيئة `PROFESSOR_API_KEY`.

## <a name="5"></a>📢 5. نظام الاشتراكات — التدفق الكامل

### رحلة المستخدم في تليجرام
```
اشتراك → اختر نوع الخدمة (📢 قناة / 📉 مؤشر)
   قناة: اختر المدة ← من قائمة channel_durations
   مؤشر: أدخل يوزر TradingView ثم اختر المدة ← indicator_durations
→ طلب معلق pending_subs + رسالة "✅ طلب الاشتراك تم إرساله"
→ تنبيه للأدمن: الرسالة القابلة للتعديل subscription_request_admin
   🟢 طلب اشتراك جديد! / الاسم / الخدمة (بالعربي) / 📉 TV / المدة
   مع زرّي [✅ قبول] [❌ رفض] في سطر واحد
```

### القبول (من التطبيق أو تليجرام)
1. المبلغ يُدخل من التطبيق (القبول السريع من تليجرام = 0 «مجاني»).
2. التفعيل: `channel_end` أو `indicator_end` = الآن + الأيام، الإيراد والعدد يُجمعان على `stats`.
3. المستخدم يستلم: رسالة الترحيب القابلة للتعديل + زر «اضغط هنا للانضمام للقناه/عرض المؤشر» + رسالة النصائح.
4. الرفض: رسالة `reject_user_channel` / `reject_user_indicator`.

### الحلقة الدورية (كل 60 ثانية)
- **قرب الانتهاء (آخر 24 ساعة، مرة واحدة عبر `notified_1day`):** المستخدم ← `subscription_expiring_*`، الأدمن ← `subscription_expiring_1day_admin`، + إشعار تطبيق.
- **انتهى الاشتراك:** المستخدم ← `subscription_ended_*`، الأدمن ← `subscription_removed_admin`، حذف الخدمة ثم حذف السجل إن لم تبقَ خدمات.

### الإدارة من التطبيق
قائمة المشتركين / المعلقين / قرب انتهائهم / المدة المتبقية / قبول (مع المبلغ) / رفض / إضافة / **حذف (جزئي قناة أو مؤشر أو الكل مع إشعار المستخدم "❌ تم إلغاء الصلاحية." والأدمن "✅ تم الحذف.")** / تمديد / إذاعة (قناة/مؤشر/الكل) / إحصائيات بنفس حقول القديم / تعديل كل النصوص / إعدادات الروابط والمدد (عرض القيمة الحالية + ✏️ تعديل + 🗑️ حذف + ➕ إضافة).

## <a name="6"></a>💼 6. نظام المسوقين — التدفق الكامل

### الانضمام والاعتماد
1. المستخدم يضغط **🤝 طلب الانضمام كمسوق** → نص القديم حرفياً → تنبيه أدمن «🔔 طلب انضمام مسوق جديد!» (الاسم + المعرف + الآيدي) مع [✅ قبول واعتماد] [❌ رفض].
2. الاعتماد (الاسم + العمولة من التطبيق، أو افتراضي من تليجرام):
   - إنشاء **رابط دعوة باسم المسوق** في القناة العامة.
   - المسوق يستلم: رسالة الترحيب التنفيذية + الرابط + العمولة ثم «📄 وثيقة العمل والشروط:» (`contract_msg`).
3. الرفض: `join_rejected` حرفياً.

### لوحة المسوق في تليجرام (كلها نصوص القديم حرفياً)
| الزر | السلوك |
|---|---|
| 💰 رصيدي الحالي | تقرير «حصاد أرباحك (معلومات تفصيلية)» — النسبة/المدفوع/معلق خاصة/معلق عامة |
| 🔗 رابطي التسويقي | الرابط مع «🚀 انسخ الرابط وانشره الآن...» |
| 💸 طلب سحب الأرباح | **طلب لكل عميل مستحق** — تنبيه أدمن «💸 طلب سحب أرباح! 🔔» بأزرار [✅ قبول ودفع] [❌ رفض] |
| 🔙 رجوع للقائمة الرئيسية | العودة للوحة الموحدة |

### دفع العمولات (مطابق للقديم — لكل عميل)
- **الدفع:** حذف العميل من `referrals` + `paid_count+1` + حذف سجل السحب + المسوق يستلم «💸 استلام عمولة: ... استمر يا بطل! 🚀» + تعديل رسالة الأدمن «✅ تمت التصفية! 💸».
- **الرفض:** العميل **يبقى معلقاً** في المستحقين + حذف سجل السحب + المسوق يستلم `withdrawal_rejected` باسم العميل الحقيقي + «❌ تم رفض طلب سحب العميل: ...».
- عميل مدفوع مكرراً: «⚠️ العميل غير موجود أو تم دفع عمولته مسبقاً.».

### إدارة الروابط (كاملة ومختبَرة)
اعتماد ← إنشاء رابط تلقائي • ♻️ تجديد (حرق القديم + جديد + إشعار المسوق `link_updated`) • 🔥 حرق رابط محدد • 🔥 حرق جميع الروابط • 🗑 حذف مسوق (سحب الصلاحية + **حرق رابطه تلقائياً** + `marketer_disabled`) — تحسين مقصود: القديم كان يترك الرابط يعمل.

## <a name="7"></a>📡 7. رادار الانضمامات و"الذاكرة الفولاذية"

معالج `track_joins` (ChatMemberHandler) — مطابق لرادار البوت القديم بكل فروعه:

| الحدث | حفظ البيانات | تنبيه الأدمن (نص القديم) | رسالة المسوق | إشعار التطبيق |
|---|---|---|---|---|
| عميل دخل العامة عبر رابط مسوق | `public_leads` + `historical_clients` | 🔔 انضمام مبدئي (للعامة) ⏳ | 👀 إشعار | `public_join` |
| نفس العميل عبر رابط آخر لاحقاً | منع الاحتساب المزدوج | ⚠️ محاولة انضمام مكررة (سد ثغرة) 🚨 | — | `duplicate_join` |
| دخل الخاصة VIP وكان lead | نقل إلى `referrals` + عدّادات | 💸 اشتراك فعلي مؤكد! (VIP) ✅ | 🎉 مبروك! اشتراك فعلي مؤكد ✅ | `vip_join` |
| دخل VIP دون مسوق | `عضوي (بدون مسوق)` | ℹ️ اشتراك جديد (عضوي) | — | `organic_vip_join` |
| عميل قديم عاد لـ VIP | تجديد — لا عمولة جديدة | 🔄 تجديد اشتراك (عميل سابق) ♻️ | — | `renewal_vip_join` |

**آلية التمييز:** اسم رابط الدعوة = اسم المسوق (صغيراً) — `invite_link.name`.

## <a name="8"></a>🔔 8. نظام الإشعارات اللحظية — القناة المباشرة الخاصة (بلا جوجل إطلاقاً)

منظومة التنبيهات **مستقلة 100% ومملوكة لك بالكامل**: لا Firebase، لا حسابات جوجل، لا ملفات سرية، لا أي طرف ثالث — والإشعار يصل **لحظياً** عبر خط مباشر حي بين التطبيق وسيرفرك.

### 8.1 مركز الإشعارات داخل التطبيق (الشاشة 🔔)

- التطبيق يسأل: `GET /api/notifications?after=<آخر آيدي>`.
- **الآيدي متزايد دائماً ولا يُصفَّر أبداً** — لذلك حذف كل الإشعارات لا يضيّع الجديدة.
- أنواع الطلبات تُعرض بأزرار إجراء داخل التطبيق (قبول/رفض/دفع) ما لم تكن `handled`.
- الحذف: زر 🗑️ واحد في الأعلى يحذف **الكل** (`/api/notifications/read {"all":true}`)؛ ويدعم `{"ids":[...]}` و`{"all":true,"processed_only":true}`.
- **سعة ثابتة = 100 إشعار بالضبط (FIFO):** لا يُحذف أي إشعار إطلاقاً إلا بطريقتين: يدوياً عبر زر سلة المهملات 🗑️، أو تلقائياً عند وصول إشعار جديد والقائمة ممتلئة (100/100) فيُحذف **أقدم إشعار فقط** ويشغل الجديد مكانه فوراً — لا اختفاء مفاجئ ولا حذف جماعي من تلقاء النظام.

### 8.2 التنبيه اللحظي خارج التطبيق — طبقات مملوكة لك بالكامل

| الطبقة | الوصف |
|---|---|
| ⚡ **القناة المباشرة الحية (SSE) — الأساس** | خيط دائم داخل الخدمة الأمامية يمسك خطاً مفتوحاً مع `GET /api/notifications/stream`؛ أي إشعار جديد يُدفع عبر الخط **في اللحظة نفسها (< ثانية)** إلى شاشة القفل. نبضة سيرفر كل 25 ثانية تُبقي الخط حياً عبر الشبكات والبروكسيات، وإعادة الاتصال تلقائية كل 4 ثوانٍ — نفس تقنية التطبيقات اللامركزية العالمية و**أقوى حل موجود بلا خدمات جوجل** |
| 🔄 **الفحص الاحتياطي (كل 60 ثانية)** | `GET /api/notifications?after=N` يلتقط أي إشعار فات أثناء انقطاع مؤقت — شبكة أمان مزدوجة مع القناة الحية عبر العداد المشترك `lastNotificationId`، فلا تكرار أبداً |
| 🛡️ **حُرّاس البقاء** | خدمة أمامية بإشعار دائم صغير (أهمية دنيا `IMPORTANCE_MIN` — مطلوب نظامياً لبقاء الخدمة، وإخفاؤه كلياً يقتل التطبيق على أندرويد 13+) + مؤقّت إيقاظ `AlarmManager` كل 5 دقائق يكسر وضع Doze + حارس `WorkManager` كل 15 دقيقة يعيد إحياء الخدمة إن قتلها النظام + `ProfessorBootReceiver` يشغّل كل شيء بعد إعادة إقلاع الهاتف + طلب **استثناء تحسين البطارية** مرة واحدة |

- **قناة إشعارات فاخرة (v2):** أهمية علوية (منبثقة فوق الشاشة) + اهتزاز مزدوج + ضوء LED ذهبي + شارة عدّاد على الأيقونة + ظهور كامل على شاشة القفل + **أيقونة كبيرة بشعار علامتك** + لون ذهبي مميز + حذف تلقائي لأي قناة قديمة.
- **منع التكرار:** القناة الحية والفحص الاحتياطي يتقاسمان العداد `lastNotificationId` — أي إشعار يظهر من مسار يتجاوزه الآخر.
- الضغط على أي إشعار يفتح التطبيق مباشرة على شاشة الإشعارات (`open_notifications` ← `openEcosystemNotifications()`).
- وحتى لو توقفت كل طبقات التطبيق لسبب ما، تظل **تنبيهات تيليجرام للأدمن (بأزرارها)** قناة وصول مضمونة دائماً.

### 8.3 التفعيل — لا شيء مطلوب إطلاقاً ⚡

النظام يعمل تلقائياً فور **ربط التطبيق بالسيرفر** من شاشة 🔗:
1. **حُذف كل ما يتعلق بجوجل نهائياً:** لا Firebase، لا `google-services.json`، لا ملفات حساب خدمة، لا مفاتيح، لا خطوات إضافية.
2. عند أول تشغيل بعد الربط يطلب التطبيق: إذن الإشعارات ثم استثناء البطارية — **وافق على الاثنين**.
3. في شاومي/هواوي/أوبو: فعّل «التشغيل التلقائي / Auto-launch» من إعدادات التطبيق لضمان ديمومة القناة الحية.
4. من تلك اللحظة تعمل القناة 24/7. جرّب بنفسك: أغلق التطبيق تماماً وأرسل طلب اشتراك من تليجرام آخر ⇒ يصل التنبيه لحظياً على شاشة القفل.

### 8.4 سلوك السيرفر في الدفع

- كل `notify(...)` (اشتراك/مسوق/سحب/رادار/أي نوع) تحفظ الإشعار ثم **تبثّه فوراً** عبر `_sse_broadcast` لكل تطبيق متصل — في خيط خفيف لا يُبطئ بوت تليجرام ولا واجهة API أبداً.
- حمولة البث خفيفة: `{id, type, title, message}` — والتطبيق يجلب التفاصيل والأزرار عند فتح الشاشة.
- إن لم يكن أحد متصلاً لحظة الإشعار: يبقى محفوظاً، ويلتقطه **الفحص الاحتياطي** خلال 60 ثانية كحد أقصى.
- نبضة `: ping` كل 25 ثانية على الخط تمنع الجدران النارية والبروكسيات من خنق الاتصال.

## <a name="9"></a>🔁 9. تنبيهات الأدمن والمزامنة الثنائية تطبيق ↔ تليجرام

**مبدأ أساسي:** الأدمن في تليجرام يستلم تنبيهات + أزرار فقط — الإدارة كلها من التطبيق.

| التنبيه | الأزرار | kind |
|---|---|---|
| طلب اشتراك | ✅ قبول `sub_accept_` / ❌ رفض `sub_reject_` | `sub` |
| طلب مسوق | ✅ قبول واعتماد `mk_accept_` / ❌ رفض `mk_reject_` | `mk` |
| طلب سحب (لكل عميل) | ✅ قبول ودفع `pay_` / ❌ رفض `rejectreq_` | `wd` |

**المزامنة:**
- إجراء من التطبيق ← تعديل رسالة تليجرام: إزالة الأزرار + سطر «✅ تم قبول هذا الطلب من التطبيق» (`deactivate_admin_alert`).
- إجراء من تليجرام ← تمييز إشعار التطبيق `handled` بنص الإجراء (`mark_notification_handled_for`).
- ضغط زر معالَج سابقاً ← «⚠️ الطلب غير موجود أو تمت معالجته من التطبيق» (أو النص الخاص بالعملية مثل «⚠️ العميل غير موجود أو تم دفع عمولته مسبقاً.»).

## <a name="13"></a>👨‍💻 13. دليل المطوّر المستقبلي

**اقرأ هذا قبل أي تعديل:**

1. **لا تغيّر نصاً ولا زراً ولا تدفقاً** دون موافقة المالك — السلوك مطابق للبوتات القديمة عمداً وتم اختباره نصاً بنص.
2. **لا إضافات («زوائد»)** من تلقاء نفسك — المالك يطلب صراحة كل ميزة جديدة.
3. الأدمن يُدار من التطبيق فقط؛ في تليجرام تنبيهات بأزرار فقط — لا تبنِ لوحة أدمن في تليجرام.
4. **إضافة تنبيه أدمن جديد:** استخدم `send_admin_alert_text(text, buttons, kind, uid)` وخزّن المرجع ليعمل إلغاء الأزرار، واستدعِ `deactivate_admin_alert/notifications` بقواعد المزامنة (§9).
5. **إضافة إشعار تطبيق:** `notify(type, title, message, extra)` — ضع `extra.user_id` ليُربط بأزرار الإجراءات والمزامنة.
6. **إضافة endpoint:** لا تضفه للمسارات العامة — الميدلوير يحميه تلقائياً. صفوف الأشخاص يجب أن تمر عبر `person_row()` (يمنع ظهور الآيدي مكرراً بدل الاسم).
7. البوت **واحد** للنظامين: `runtime.sub_app` و`runtime.marketing_app` لنفس الـ Application — استخدم `runtime.main_bot()`.
8. بيانات تليجرام غير قابلة للاختبار محلياً — نمط المشروع: بوت وهمي `FakeBot` يسجّل `send_message/create_chat_invite_link/revoke_chat_invite_link` ثم اختبارات `asyncio` مباشرة على الدوال (انظر اختباراتنا: 21 فحص مسوقين + 14 رادار/روابط + 11 تنبيهات/حذف — كلها PASS).
9. قبل التسليم دائماً: `python -m py_compile main.py` + فحص JS (`node --check`) + إعادة بناء الحزم **من الصفر** (`rm -f` للقديم أولاً — الحذف النسبي للملفات يسبب بقايا).

**أماكن التعديل الشائعة:**

| ماذا تريد | أين |
|---|---|
| نص رسالة بوت | `config.json` (أو من التطبيق) — لا تعدّل الكود |
| مدة اشتراك جديدة | من التطبيق ← إعدادات المدد |
| منطق قبول/رفض | `approve_subscriber`, `approve_marketer`, `do_pay_client` في `main.py` |
| رادار الانضمامات | `BotRuntime.track_joins` |
| واجهة شاشة إدارة | `professor.html` (أقسام step_ecosystem_*) |

## <a name="14"></a>🩹 14. استكشاف الأخطاء

| العَرَض | السبب | الحل |
|---|---|---|
| `401 Invalid API key` | مفتاح قديم في التطبيق | زر 🔑 لفتح شاشة المفتاح المنبثقة ونسخه، أو إعادة الربط |
| الروابط/المدد تظهر «غير محدد» أو صفر | السيرفر العامل نسخة **قديمة** من main.py، أو ملف محفوظ بأسماء مفاتيح قديمة | ارفع main.py الجديد + Restart؛ النسخة الجديدة تملك **إصلاحاً ذاتياً (Self-Healing)**: `cfg()` تسترجع القيم من كل الأسماء القديمة (`vip_channel_link`، `indicator_url`، `support`، `durations:{channel,indicator}`...) وتعيد كتابة الملف مصححاً تلقائياً. إن كانت النسخة القديمة قد أسقطت القيم أصلاً: افتح شاشة التهيئة السيرفر مرة واحدة (ستجد القيم المسترجعة ظاهرة)، أكمل الناقص واحفظ — ولن تتكرر أبداً |
| فشل إنشاء رابط المسوق | البوت ليس مشرفاً في القناة العامة | ارفعه مشرفاً ثم أعد الاعتماد/التجديد |
| لا تنبيهات في التطبيق | السيرفر لم يُشغَّل بعد رفع main.py جديد | Restart في KataBump |
| الرادار لا يرصد القناة العامة | الانضمام ليس عبر رابط دعوة باسم مسوق | الرادار يعمل فقط على روابط المسوقين (كالقديم) |
| أسماء تظهر كآيدي | بيانات قديمة بلا أسماء | تُحلّ تلقائياً مع الطلبات الجديدة؛ القوائم تمر بـ `person_row` |
| التطبيق لا يتصل HTTP | استخدم منفذ التوجيه الخارجي لـ KataBump مع الـ IP | مثال: `http://IP:PORT` |

## <a name="15"></a>📈 15. نظام إدارة وإرسال الصفقات (محلي بالكامل داخل التطبيق)

هذا النظام **مستقل تماماً عن السيرفر** — التسجيل والأرشفة والقوالب تعمل محلياً 100% على جهازك، والإرسال يذهب مباشرة لقنواتك عبر بوتك في تليجرام. سجل صفقاتك وملاحظاتك وصورك لا تغادر هاتفك إلا عند إرسالك رسالة لقناتك أنت.

### 15.1 رحلة الصفقة — زر جاهز لكل مرحلة

| المرحلة | الزر | ما يحدث |
|---|---|---|
| 1️⃣ التنبيه الأولي | شراء 🟢 / بيع 🔴 | تكتب سعر الدخول فقط ← رسالة تنبيه أولي فورية لقنواتك المختارة |
| 2️⃣ تفاصيل الصفقة | زر الإرسال | الدخول + الاستوب + حتى **4 أهداف** ← رسالة تفاصيل مع حساب النقاط تلقائياً |
| ⏳ تحديث الربح | `تحديث الربح الآن` | تكتب النقاط المحققة ← رسالة تحديث + حفظ **أعلى ربح** وصلته الصفقة |
| 🛡️ تأمين الصفقة | `تأمين الصفقة` | رسالة نقل الوقف لنقطة الدخول — تُنفَّذ **مرة واحدة فقط** (التطبيق يمنع التكرار) |
| 🎯 ضرب الهدف | الهدف 1/2/3/4 من تفاصيل الصفقة | رسالة ضرب الهدف بنقاطه وحصيلته التراكمية |
| 💎 إغلاق رابح | `إغلاق رابح (الهدف الأول)` | إغلاق سريع بحصيلة الهدف الأول |
| 🛑 ضرب الاستوب | `ضرب الاستوب` | رسالة الإغلاق بنقاط الاستوب السالبة |
| ⚖️ ضرب التأمين / إغلاق | `ضرب تأمين (إغلاق)` | رسالة إغلاق صفري (0 نقطة) |

- **حاسبة نقاط الذهب:** الخوارزمية مضبوطة لحركة الذهب: `النقاط = |السعر - سعر الدخول| × 10` (كل حركة 0.10 تساوي نقطة).
- كل رسالة تُبنى من قالبك وتوقَّع باسم **علامتك التجارية** (`prof_brand_name` من الإعدادات العامة).

### 15.2 قوالب الرسائل السبعة — قابلة للتعديل بالكامل

تُعدَّل من شاشة «الإعدادات العامة والرسائل» (الخطوة 7) أو من بطاقة تهيئة القوالب، وتُحفظ محلياً مع إمكانية استعادة الأصل:

| القالب | المفتاح | المتغيرات المتاحة |
|---|---|---|
| التنبيه الأولي | `firstAlert` | `{نوع الصفقة}` `{اتجاه الصفقة}` `{سعر الدخول}` |
| تفاصيل الصفقة | `tradeDetails` | `{نوع الصفقة}` `{أيقونة الصفقة}` `{سعر الدخول}` `{الاستوب}` `{نقاط الاستوب}` + `{الهدف الأول}` `{نقاط الهدف الأول}` … حتى `{الهدف الرابع}` `{نقاط الهدف الرابع}` + `{تفاصيل الصفقة}` `{اسم العلامة}` |
| تأمين الصفقة | `secureEntry` | `{نوع الصفقة}` `{سعر الدخول}` |
| تحديث الربح | `profitUpdate` | `{نوع الصفقة}` `{نقاط الربح}` |
| ضرب الهدف | `targetHit` | `{نوع الصفقة}` `{اسم الهدف}` `{نقاط الهدف}` `{الحصيلة}` `{أعلى ربح}` |
| ضرب الاستوب | `stopHit` | `{نوع الصفقة}` `{نقاط الاستوب}` `{الحصيلة}` `{أعلى ربح}` |
| الإغلاق اليدوي/ضرب التأمين | `manualClose` | `{نوع الصفقة}` `{الحصيلة}` `{أعلى ربح}` |

### 15.3 الإرسال لتليجرام والقنوات المتعددة

- الإرسال عبر جسر `Android.sendTelegram(...)` — طلب Bot API آمن (HTTPS) يتم ناتيفياً من التطبيق ويعيد النجاح/الخطأ للواجهة.
- **توجيه متعدد القنوات:** لكل صفقة قنوات هدف محفوظة (`routeChatIds`) — حدّد من الإعدادات العامة القنوات التي يقبلها البوت ثم اختر وجهة كل رسالة.
- تسجيل الصفقة وأرشفتها وحساباتها محلية دائماً وتعمل بلا إنترنت؛ أمّا إرسال الرسائل فيحتاج اتصالاً لتنفيذ طلب تليجرام.

### 15.4 الأرشيف والتوثيق لكل صفقة

- سجل كامل: النوع، الدخول، الاستوب، الأهداف ونقاطها، النتيجة (رابحة/خاسرة/تعادل)، النقاط، أعلى ربح، وقت وتاريخ الفتح بالعربية.
- **خط زمني للأحداث** داخل كل صفقة (وقت + حدث): الدخول، تحديد الأهداف، التأمين، كل تحديث ربح، ضرب الأهداف/الاستوب.
- **صورة توثيقية** لكل صفقة (اختيار من المعرض + معاينة + حذف) و**ملاحظات سرية** خاصة بك لا تُرسل أبداً لأي جهة.
- إضافة **صفقة سابقة** يدوياً لأرشفة تاريخك، فرز القائمة ↕️، وتعديل بيانات أي صفقة يدوياً.
- **بطاقة توثيق PDF فاخرة** لكل صفقة باسم علامتك (زر الطباعة في شاشة التفاصيل) — تُحفظ وتُشارك كإثبات احترافي.

### 15.5 التقارير — «حصاد الصفقات» واستخراج بالتاريخ

- **الحصاد العام (الخطوة 5):** إجمالي الصفقات، شراء/بيع، رابحة/خاسرة/تعادل، **الصافي لأول هدف فقط** و**الصافي النهائي لكل الأهداف**.
- **استخراج بالتاريخ (الخطوة 4):** حدّد «من تاريخ» و«إلى تاريخ» ثم «📊 تقرير مختصر» أو «📜 تقرير مفصل (السجل الكامل)».
- توزيع الربح/الخسارة بالنقاط وفق حصيلة كل صفقة المسجلة.

### 15.6 النسخ الاحتياطي

- تحميل/استعادة كامل سجل الصفقات وبياناتها (ملف JSON) من زر «النسخ الاحتياطي واستعادة الصفقات» في شاشة الإعدادات العامة.
- **تذكير ذكي تلقائي كل 50 صفقة** يوصي بأخذ نسخة لحماية السجل والصور.

### 15.7 النافذة العائمة والاختصار السريع

- 🫧 **النافذة العائمة (Floating Bubble):** صغّر التطبيق لفقاعة تطفو فوق MT4/MT5 أو تليجرام — تنقل الأرقام وترسل الصفقة وأنت على المنصة نفسها دون تبديل التطبيقات (تتطلب إذن «الظهور فوق التطبيقات»).
- ⚡ **اختصار الإعدادات السريعة (Quick Settings Tile):** اسحب شريط الحالة ← «تعديل» ← أضِف أيقونة PROFESSOR بجوار الواي فاي، فيفتح التطبيق فورياً بضغطة من أي شاشة.

### 16.1 شاشات نظام الصفقات (محلية)

| الشاشة | الوظيفة |
|---|---|
| الرئيسية (step1) | بطاقة علامتك التجارية + قائمة: لوحة التحكم وإدارة الصفقات، استخراج التقارير، الإعدادات |
| تفاصيل الصفقة (step2) | إدخال الدخول/الاستوب/الأهداف (حتى 4) وإرسال رسالة التفاصيل |
| إدارة الصفقة الحالية (step3) | تحديث الربح الآن / إغلاق رابح / ضرب الاستوب / تأمين الصفقة / ضرب تأمين (إغلاق) |
| استخراج التقارير (step4) | من تاريخ/إلى تاريخ ← 📊 تقرير مختصر أو 📜 تقرير مفصل |
| حصاد الصفقات (step5) | إجماليات الفترة كلها: العدد، شراء/بيع، رابحة/خاسرة/تعادل، الصافيان |
| السجل المفصل (step6) | بطاقات كل الصفقات بالتتابع + صافي النقاط في الأسفل |
| الإعدادات العامة والرسائل (step7) | تعديل البوت والقنوات والبراند + محرر القوالب السبعة + النسخ الاحتياطي |
| لوحة التحكم (step_dashboard) | كل صفقاتك (الجارية والمؤرشفة) + ➕ صفقة سابقة + فرز ↕️ |
| تفاصيل صفقة (step_trade_detail) | الخط الزمني + إرفاق/حذف صورة + ملاحظات سرية + تعديل يدوي + طباعة بطاقة PDF |

### 16.2 شاشات المنظومة (متصلة بالسيرفر)

| الشاشة | الوظيفة |
|---|---|
| ربط السيرفر 🔗 | إدخال الرابط + مفتاح API + معرف العميل (يدوي أو عبر رابط الاقتران من صفحة الخادم) |
| الرئيسية للمنظومة | مركز القيادة: مشتركين، مسوقين، إشعارات، إعدادات، تهيئة، اختبار البوت 🔑 |
| الإشعارات 🔔 | القائمة (حتى 100 — FIFO) + أزرار قبول/رفض/دفع للطلبات + 🗑️ حذف يدوي |
| المشتركين | قائمة المشتركين + 📊 إحصائيات عامة (بنفس السطر)، رسالة للكل، حذف مشترك، وداخل القائمة: المعلقون، قارب انتهائهم، إضافة/تمديد (الاسم — id) |
| إعدادات المشتركين ⚙️ «الإعدادات» | **تعرض القيم الحالية دائماً قبل التعديل:** روابط القناة/المؤشر/الدعم + مدد الخدمتين (عرض/إضافة/تعديل/حذف) + ✏️ تعديل النصوص |
| رسائل المشتركين | محرر كل نصوص المشترك مع عرض القيمة الحالية |
| المسوقون | معلومات مسوق، تحديد/تعديل عمولة، كشف العملاء المعلقين، إحصائيات، فحص مصدر عميل، 🗑 حذف مسوق |
| إعدادات التسويق | رسالة العقد، تجديد رابط، حرق رابط محدد/الكل |
| طابور الإرسال 📬 | مراقبة التنبيهات المعلقة لتليجرام: عدد المعلق/الجاري، اسم القناة، عدد المحاولات، موعد المحاولة القادمة + أزرار: إرسال الآن، حذف رسالة، حذف رسائل قناة، تفريغ الكل + كشف تلقائي للقناة المتعثرة (20+ محاولة بإطار ذهبي) |
| تهيئة الرسائل | محرر رسائل المنظومة (اشتراكات + تسويق) ضمن المعالج |
| إعداد السيرفر (المعالج) | التوكن، الأدمن، القنوات، الروابط، المدد، الرسائل — **يُحمّل القيم الحالية من السيرفر عند فتحه** |
